# Quickstart & 検証ガイド: AsuMe

本書は AsuMe を起動し、spec の主要シナリオが end-to-end で動くことを検証する手順。実装詳細は [plan.md](./plan.md) / [contracts/](./contracts/) を参照。

## 前提

- Node.js（`package.json` の依存をインストール済み）。
- 自動生成機能を試す場合は `.env.local` に外部 API キーを設定（学習・クイズのみなら不要）:
  ```
  WORDS_API_KEY=...      # RapidAPI WordsAPI
  DEEPL_API_KEY=...       # DeepL（generate の翻訳フォールバック）
  OPENAI_API_KEY=...      # OpenAI（推奨。enrich は必須）
  # レート制限を有効化する場合は Upstash の接続情報も設定
  ```

## セットアップ & 起動

```bash
npm install
npm run dev      # http://localhost:3000
```

## ユニットテスト（ロジック検証）

```bash
npm run test     # Jest: csvParser / projectManager / quizEngine
```

期待: 既存テストが全てパス。ロジック変更時は対応する `*.test.ts` を先に更新（TDD）。

## 検証シナリオ（spec のユーザーストーリー対応）

### S1. CSV 取り込み → 4択クイズ（US1 / P1）

1. ホーム `/` で `words`・`japanese` を含む CSV をアップロード。
2. 単語帳が作成されることを確認（空 `words` 行は除外、`japanese` 空欄があれば警告）。
3. `/quiz/[projectId]` でクイズ開始 → 同一帳の他単語からダミー3つの4択が最大10問出題。
4. わざと誤答 → その問題が同セット内で再出題されることを確認。
5. 単語の読み上げが正しい英語発音（活用形含む）であることを確認。

### S2. 学習履歴と殿堂入り（US2 / P2）

1. 同じ単語帳を複数セット学習。
2. ある単語を3回連続正解 → 以降の通常出題に現れない（殿堂入り）。
3. 未回答・低正答率の単語が優先出題されることを確認。
4. 「復習」で直近誤答が集中出題されることを確認。

### S3. 英単語から自動生成（US3 / P3）※要 API キー

1. `/generator` で英単語を数件入力し生成実行。
2. 進捗バーと結果プレビューが1件ずつ更新される（`POST /api/generate`）。
3. 各単語に訳・例文（対象語が `_`/`_[活用形:…]`）・発音・品詞が付与される。
4. 多義語（例: record）で品詞に整合する訳・発音になることを確認。

### S4. 管理と一括補完（US4 / P3）

1. `/manage/[projectId]` で単語の追加/修正/削除・殿堂入りリセット・名称インライン変更。
2. 訳/例文が空欄の帳で一括補完バナー → `POST /api/enrich` が順次実行され空欄が埋まる。

### S5. バックアップ/復元/CSV書き出し（US5 / P3）

1. ホームから ZIP エクスポート。
2. データ削除後に ZIP インポート → 単語と進捗が復元。
3. CSV エクスポート → 表計算ソフトで日本語が文字化けしない（BOM付き）。

## レート制限の確認（任意）

Upstash 設定時、`429` 受信でフロントの一括補完ループが中断し上限到達メッセージが出ることを確認（`proxy.ts` / `rateLimit.ts`、定数 2450/200）。
