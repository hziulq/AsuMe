# Feature Specification: クイズのゲーミフィケーション（解答タイマー＋称賛演出）

**Feature Branch**: `002-quiz-gamification`

**Created**: 2026-06-30

**Status**: Draft

**Input**: ユーザー要望: 「ゲーミフィケーションを追加したい。解答の時間制限や、全問回答後はプレイヤーをほめるような演出が欲しい」＋会話での確定事項（タイムアウト挙動・称賛演出）。

## Overview

既存の4択クイズに、(1) 1問ごとの**解答タイマー**による程よい緊張感と、(2) セット完了時の**称賛・達成演出**を加え、学習のテンポと「もう1セットやりたい」という継続動機を高める。タイマーは既存の学習履歴（連続正解での殿堂入り・復習キュー）と整合する形で結果に反映する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 解答タイマーとタイムアウトの扱い (Priority: P1)

学習者は制限時間つきで各問に挑む。時間内に正解できれば通常どおり正解。時間切れになっても問題は勝手に飛ばされず、学習者はそのまま解答できるが、その回答は「タイムアウト」として結果に明示され、内部的には失敗（不正解相当）として記録される。

**Why this priority**: ゲーミフィケーションの核となる「時間という挑戦要素」。これ単体で体験が成立する。

**Independent Test**: タイム制限モードで1問に挑み、(a) 時間内正解、(b) 時間切れ後に正解、(c) 時間切れ後に誤答、の3パターンで、結果表示と学習履歴への反映が仕様どおりになることを確認すれば検証できる。

**Acceptance Scenarios**:

1. **Given** タイム制限モードで出題中、**When** 制限時間内に正解を選ぶ、**Then** 通常の正解として扱われ、連続正解数が加算される。
2. **Given** 出題中に制限時間が切れる、**When** タイマーが0に達する、**Then** 問題は**自動スキップ／自動送信されず**、学習者はそのまま選択肢を解答できる。
3. **Given** 時間切れ後に正解を選ぶ、**When** 回答を確定する、**Then** UI上は「正解」を示しつつ**「時間切れ」であることを明示**し、内部的には失敗として扱う（連続正解数はリセット、復習キューに追加、セット内で再出題）。
4. **Given** 時間切れ後に誤答を選ぶ、**When** 回答を確定する、**Then** 「不正解」かつ「時間切れ」として表示し、失敗として記録する。
5. **Given** タイム制限モードがオフ、**When** クイズを行う、**Then** タイマーは表示されず、タイムアウトの概念は適用されない（従来どおりの学習）。

### User Story 2 - セット完了時の「ドキドキ」正解数カウントアップ演出 (Priority: P1)

学習者が1セット（最大10問）を完了すると、毎回、正解数を高揚感のある演出でカウントアップ表示し、達成を実感できる。

**Why this priority**: 全プレイで必ず得られる即時報酬。継続動機の中心。

**Independent Test**: 任意の成績でセットを完了し、正解数のカウントアップ演出が表示され、約2秒で終了することを確認すれば検証できる。

**Acceptance Scenarios**:

1. **Given** 1セットを完了、**When** 結果画面に入る、**Then** 正解数を0から実数までカウントアップする「ドキドキする」演出が表示される。
2. **Given** カウントアップ演出、**When** 開始からおよそ2秒経過、**Then** 演出は終了し、結果と次アクション（次セットへ等）が操作可能になる。
3. **Given** 成績の良し悪しに関わらず、**When** セットを完了、**Then** カウントアップ演出は**常に**表示される。

### User Story 3 - 全問正解時の特別な称賛演出 (Priority: P2)

学習者がそのセットを全問正解したときのみ、「全問正解おめでとう！」のような特別な称賛演出が追加で表示され、達成感が強調される。

**Why this priority**: 上振れ時の特別感。P1の基本演出があれば成立するため P2。

**Independent Test**: 全問正解のセットと、1問でも失敗したセットをそれぞれ完了し、特別演出の有無が切り替わることを確認すれば検証できる。

**Acceptance Scenarios**:

1. **Given** セットの全問を「初回提示で・時間内に」正解、**When** セットを完了、**Then** カウントアップ演出に加えて「全問正解おめでとう！」の特別演出を表示する。
2. **Given** 1問でも失敗（誤答またはタイムアウト）がある、**When** セットを完了、**Then** 特別演出は表示されず、通常のカウントアップ演出のみとなる。

### Edge Cases

- 時間切れ後も解答可能なため、タイマーが0でも入力は無効化しない。0到達時はUIで「時間切れ」状態を明示する。
- 失敗（誤答／タイムアウト）した問題は既存仕様どおりセット内で再出題される。再提示時も各表示にタイマーが付く。ただし「正解数／全問正解」の判定は**初回提示時**の結果で確定する（再出題での正解はカウントに含めない）。
- セットが1問のみでも、カウントアップ演出と（全問正解時の）特別演出は機能する。
- タイム制限モードがオフのときも、セット完了のカウントアップ演出は表示される（タイムアウトの概念のみ無効）。
- 演出中に学習者が次へ進もうとした場合でも、操作不能で待たされ続けない（約2秒で終了し、即継続できる）。

## Requirements *(mandatory)*

### Functional Requirements

**解答タイマー**
- **FR-001**: System MUST タイム制限モードが有効なとき、各問に残り時間が見えるカウントダウンを表示する。
- **FR-002**: System MUST 制限時間が0に達しても、問題を自動スキップ／自動送信せず、学習者が引き続き解答できる状態を保つ。
- **FR-003**: System MUST 制限時間切れ後に確定された回答を「タイムアウト」として扱い、正誤に関わらず学習上は**失敗**とする（連続正解数リセット、復習キューに追加、セット内で再出題）。
- **FR-004**: System MUST 回答後のフィードバックで「時間内正解」「時間切れだが正解」「不正解（時間切れ含む）」を区別して表示し、タイムアウトを明示する。
- **FR-005**: Users MUST be able to タイム制限モードのオン／オフを切り替えられ、オフ時はタイマーとタイムアウト処理を一切行わない。

**称賛・達成演出**
- **FR-006**: System MUST セット完了時に毎回、正解数を高揚感のある演出でカウントアップ表示し、その演出はおよそ2秒で終了する。
- **FR-007**: System MUST カウントアップ演出の終了後、結果と次アクションを遅延なく操作可能にする（既存のシームレス継続フローを妨げない）。
- **FR-008**: System MUST セットを全問正解（全問を初回提示で・タイム制限時は時間内に正解）したときのみ、特別な称賛演出を追加表示する。
- **FR-009**: System MUST 1問でも失敗があるセットでは特別演出を表示しない。

**集計とデータ**
- **FR-010**: System MUST 「正解数」「全問正解か」を、各問の**初回提示時**の結果（タイム制限時は時間内正解か）で判定する。
- **FR-011**: System MUST タイマー・成績集計・演出をすべてデバイス内で処理し、本機能のために外部サービスへ追加送信しない（ローカル完結の原則）。

**アクセシビリティ（推奨）**
- **FR-012**: System SHOULD 演出を視覚効果のみに依存させず、テキストでも結果（正解数・全問正解）を伝える。

### Key Entities *(include if feature involves data)*

- **解答タイマー状態（一時）**: 当該問題の残り時間と「時間切れ」フラグ。永続化しない。
- **回答結果（一時）**: 正誤に加え「タイムアウトか」を保持。学習履歴へは失敗/成功として反映（既存 `QuestionData` の履歴更新に接続）。
- **セット結果サマリ（一時）**: 初回提示ベースの正解数・総問題数・全問正解フラグ。称賛演出の入力に用い、永続化しない。

> 既存エンティティ（`QuestionData` の `consecutiveCorrectCount`/`isMastered`、`Project.wrongQuestionIds`）への反映は機能001のリバース仕様 [specs/001-asume-product-overview](../001-asume-product-overview/spec.md) に準拠。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: タイム制限モードで、各問にカウントダウンが表示され、0到達時に問題が自動で進まず、学習者が引き続き解答できる（自動スキップ発生率0%）。
- **SC-002**: 制限時間切れ後の正解は100%「失敗」として記録され（連続正解数が加算されない）、結果UIで「時間切れ」と明示される。
- **SC-003**: すべてのセット完了で正解数カウントアップ演出が表示され、開始から約2秒（目安2.0秒、許容±0.5秒）で終了する。
- **SC-004**: 全問正解のセットでのみ特別称賛演出が表示され、非全問正解のセットでは表示されない（誤表示率0%）。
- **SC-005**: タイム制限モードをオフにすると、タイマー・タイムアウトなしで従来どおり学習でき、既存の学習フローにリグレッションがない。
- **SC-006**: 演出終了後、追加操作なしに次セットへ継続でき、結果画面到達から次セット開始までの待ち時間が体感で増えない。

## Assumptions

- **[要確認・暫定]** タイム制限モードは**学習開始画面でのオプトイン（既定オフ）**とする。常時オン／プロジェクト単位設定が望ましければ変更可能。
- **[要確認・暫定]** 1問あたりの制限時間の初期値は**15秒**（調整可能な設定値）とする。
- 「正解数／全問正解」は**初回提示時**の結果で判定する（既存仕様で失敗問題はセット内再出題されるため、再出題正解は集計に含めない）。
- セット完了のカウントアップ演出は、タイム制限のオン／オフに関わらず表示する（タイムアウトの概念のみモード依存）。
- 称賛演出の基本は視覚＋テキスト。音声（既存TTS）での称賛は任意拡張とし、本機能では外部サービスを新規追加しない。
- 本機能は既存のクイズエンジン（1セット最大10問・失敗問題の再出題）と学習履歴アルゴリズムの上に積み増す前提。

## Dependencies

- 既存クイズフロー（`/quiz/[projectId]`、結果画面、シームレス継続フッター）。
- 既存の学習履歴更新ロジック（連続正解・復習キュー・殿堂入り）— タイムアウトは「失敗」としてこれらに接続する。
